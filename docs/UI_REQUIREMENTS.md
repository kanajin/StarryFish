# StarryFish 界面需求

2026-10-22 修订，适用于 v0.1.10；发布结果以对应 Release 为准，合成测试不代表真实浏览器验收。

## 双窗切换与贴边（v0.1.10）

- 打开双窗时一次拓宽外框，主游戏及已停靠助手保持视口宽高；外框与布局到位后才创建并加载左侧副窗。关闭时先隐藏并卸载副窗，此前不改变外框，再一次收窄。切换不使用外框宽度动画。
- 每次切换只提交一次目标外框，抑制该调用递归触发的布局，再批量定位游戏、助手原生容器及外壳控件；保留 WebView 的尺寸/可见性缓存，只在实际屏幕位置变化时通知 WebView。副窗创建门禁直到最终布局完成才解除，不依赖动画计时器或合成器等待。
- 优先向左扩宽并固定主游戏的屏幕位置；左侧不足但整个工作区可容纳时，左边贴工作区边界，剩余宽度向右扩展。按可见边框判断空间，允许 Windows 不可见缩放边框位于工作区外；上下拉满、右侧贴边不应误报左侧不足。不因打开双窗自动缩小游戏，整个工作区不够时保留单窗。
- 未手动移动、调整尺寸或改变布局时，关闭双窗恢复开启前的位置与宽度；手动改变几何或显示器/DPI 改变后，放弃旧位置快照，按当前布局收起。真正最大化/最小化时须先还原。
- 同步箭头每次只把右侧实际游戏网址导航到副窗，相同网址则只刷新副窗；整个外框、主游戏和助手的位置尺寸保持不变。页面加载时菜单测量只更新缓存，不驱动整窗伸缩；下一次明确开关双窗或菜单设置才采用新测量。未知菜单宽度时预留完整宽度。
- 同步提交期间重复切换不重入；提交结束后正常处理标签、手动调整或系统窗口操作。副窗创建失败回退单窗，不停止主游戏；已关闭副窗的迟到创建回调不可复活旧视图。布局完成后保存，不改变现有设置格式。
- 本轮自动检查覆盖几何、单次提交、创建门禁、取消/失败与固定视口。用户已确认贴边、左侧不足时右扩及最终一次到位版本的双窗开关无畸变；该反馈不扩大为所有 DPI、显示器和助手组合均已实测。

## 正常退出（v0.1.10）

- 点击关闭后保存布局并关闭 WebView；页面脚本、图标和资源内容读取不作为退出前必须收到的回调，迟到结果不得访问已关闭或已销毁的宿主。重复关闭只继续收尾。
- 仍须完成在途控制器创建与磁盘任务，保留消息泵和资料/程序锁，直到本次运行库进程确认退出。进程观察独立于缓存计时器；不强杀浏览器，不操作其他进程，不更改资料格式。
- 用户已确认最终候选退出正常；回调取消、重复、迟到及宿主销毁另有隔离检查覆盖。

## 功能菜单与技能 CD 条（v0.1.9）

- 三点菜单新增二级“功能”菜单：技能 CD 悬浮条、左侧 moba 栏、副窗口右侧菜单、隐藏 GBF 加载小人和文字、网络抓取（MCP）、停止网络抓取、清除网络抓取记录。缓存、主题、布局等仍留在原层级。
- CD 条默认关闭，不跨重启恢复监听。菜单带勾选开关；右上角关闭按钮只在鼠标接近右侧时显现，关闭后可从菜单重开。
- 原生细条显示四名前排、每人四格，按角色位置与技能序号固定排列：正数为服务端剩余回合，亮格为 CD 0，× 为已返回技能列表中缺少的技能，? 为尚未取得或无法可信解析的数据。CD 0 不承诺未被封印、未死亡或满足使用条件。
- 浅蓝/深蓝样式跟随宿主主题，支持 DPI 缩放。可拖动到浏览器内容区域任意位置，移动/缩放宿主后保持在可见范围。属于浏览器的非激活悬浮窗，覆盖 WebView，但不设置全桌面置顶；最小化或宿主被模态窗口禁用时隐藏。
- 四个角色组之间增加留白和竖向分隔线。右下角有缩放手柄，拖动时整体等比例缩放（字号、方格、间距与点击区域同步），手动范围 50%–200%，双击手柄恢复 100%；系统 DPI 另行叠加，超出宿主可见区域时自动缩小。位置不因普通缩放按倍率移动，触及窗口边界时约束在窗内。本次运行内关闭/重开保留比例，不跨重启保存。
- 主窗（含当前普通 GBF 标签）与副窗各自保存最小 CD 快照，跟随最后实际点击的可见游戏视图，标明主窗/副窗；关掉副窗或切换主标签时回到可见视图。助手点击不改游戏数据来源。
- 开启期间连续被动监听，不依赖 MCP 是否采集，也不受 MCP 限时模式的 2/10 分钟期限影响。与 MCP 共用 Network 观察器；开关、停止/清除 MCP 不互相关闭另一消费者。不主动刷新、不发游戏请求、不点击、不修改网页游戏状态。
- 对可信 GBF 游戏文档发起的 `/rest/raid/*.json`、`/rest/multiraid/*.json` 响应，从根 `ability` 或 `status.ability` 提取 `list[技能序号][0]["ability-recast"]`，按零基 `pos` 映射。正文回取后立即更新，不等待动画完成、不按本地回合或默认 CD 推算；技能使用、刷新、攻击和同结构的其他结算都走同一解析路径。
- 仅保留当前四乘四数值和必要的异步关联状态，原始响应不为本功能落盘或存入抓包缓存。刷新、跨战斗路由、关闭/重开或视图销毁使旧异步结果失效；较旧请求的迟到快照不能覆盖较新快照。正文缺失、已知结算没有可信快照等显示 ?，不猜测为 0。
- 已有真实抓包确认多人战斗初始化、普通攻击、技能使用路径，并由用户确认随机技能变化分析正确及悬浮条显示、分隔与缩放版本可用。双窗切换、死亡/换人/封印、其他战斗模式及响应相对动画时序仍须进一步实测；协议改变或不返回上述快照的事件不保证可解析。

## 标签与地址栏

- 两种布局的标签页仅显示网页 favicon，不显示标题或标签关闭按钮。网页标题保留在悬停提示中；没有可用 favicon 时显示中性网页图标。
- 常规标签为 32 逻辑像素宽，容纳 16 逻辑像素图标和两侧留白，标签间距为 4 逻辑像素。空间不足时共同缩短推进距离，让右边标签覆盖左边标签；不显示原生左右滚动箭头，不规定最小可点击宽度。
- 绘制和点击按同一重叠顺序，右边标签优先；选中的标签不抬到后续标签上方。
- 保留两布局的＋、Ctrl+T、Ctrl+W、中键关闭普通标签、Ctrl+Tab 切换。固定 GBF 主标签保持不可关闭。
- 布局1的地址栏外框宽度为此前同等窗口宽度及 DPI 下的三分之二；地址栏左侧增加刷新图标。布局2原刷新图标保留。两者刷新右侧当前标签。
- 布局1继续保留右侧功能栏，布局2继续使用双排顶部；主题、游戏区宽度、助手位置和网页样式沿用既有需求。

## GBF 加载画面显示（v0.1.7）

- 三点菜单的“功能”二级菜单提供带勾选状态的“隐藏GBF加载小人和文字”；默认未勾选，勾选后隐藏加载角色和“Now Loading...”文字，取消后恢复原网页显示（旧发行版入口在三点菜单根层）。
- 开关按本安装全局保存，资料切换与重开沿用；当前已打开的主游戏、副游戏及普通GBF标签即时应用，无需刷新。每份新文档重新读取宿主当前值，后插入的加载角色同样受样式控制。
- 仅作用于 `https://game.granbluefantasy.jp` 顶层页面中 `#mobage-game-container` 下原版 `#ready` / `#loading` 的已知角色及文字子层。通过透明度隐藏，原加载遮罩、点击阻挡、布局、加载时序及网络请求保持原行为；加载期间可呈现原来的暗色空白底。
- 注册及偏好传递是异步的，首帧绝对无闪现尚不保证；如GBF更改这些加载层结构，可能需更新选择器。真实画面隐藏、关闭恢复和重开记忆待用户用指定开发EXE反馈，不以合成检查代替。

## GBF 后退与前进（本地候选）

- 鼠标侧键、键盘后退/前进及固定助手转发的明确导航，在可信 GBF 顶层 `/#` 路由中使用页面的实际会话历史逐项后退/前进。普通网页沿用 WebView2 的浏览器后退/前进接口。
- 对选召唤石进入战斗、后退到选召唤石后被 GBF 自动转回战斗的场景，后续点击继续遍历真实会话历史；不因浏览器 UI 将脚本跳转历史标记为可跳过就提前停止。不记忆、重建或替换选召唤石 URL，游戏自己的跳转及状态核对继续生效。若游戏本身删除或替换了历史条目，宿主不补造条目。
- 匿名普通 Chromium 浏览器实际访问用户提供的选召唤石 URL 后回到 `#top`，未进入真实战斗；隔离 `data:` 页被浏览器策略拒绝。当前机制依据 Chromium 官方历史介入说明与本地源码检查，真实战斗中的连续侧键行为仍待用户定向反馈。

## Mobage 关闭后登录接续（本地候选）

- Mobage 登录弹窗关闭后先等待 750ms，让原 SDK 授权消息及游戏导航完成；若原主游戏文档、导航代数和弹窗意图都未改变，且仍在固定游戏入口地址并显示“ログインするアカウントを選択してください。”的可见渠道选择提示，刷新原游戏页一次，让网页重新核对已存在的登录状态。
- 主页面已导航、弹窗重新打开、资料/文档更换、程序关闭或进入战斗/任意其他网址时取消接续。不会循环刷新、伪造认证成功、重放认证地址、读取凭据或改变 Cookie/权限。无法识别的渠道UI保留原行为。
- 原生 `window.opener` 与同资料 WebView2 弹窗保留。合成检查与构建不能证明真实登录已恢复，待受影响用户正常登录的定向反馈。

## ZeroOmega 代理菜单

- 从当前资料的原版 ZeroOmega worker 读取用户实际配置的情景名称，加入代理菜单；直连显示中文，其余名称按原配置显示。
- 点击一个模式时使用原版 `applyProfile`，不重置或覆盖用户配置，不触发规则自动更新。
- 模式应用并核对成功后，先持久保存宿主成功选择、再回复允许通过原版 `patch` 将启动偏好设为“使用上次模式”（原版空值语义），并再次核对保存结果和实际代理；退出重开沿用原版记忆及宿主成功选择。所有选择保存同一空值，不将较早模式名在异步回复中写回。新资料不再预置“固定启动直连”，只读核对不写配置；保存回复失败不自动重试。该单项启动偏好更新不修改各情景模式的代理地址、规则或认证信息；若用户启用了ZeroOmega配置同步，该值沿用原版同步行为。已有资料需在新版成功选择一次模式以更新旧启动偏好，不重置或重新导入。
- 当前模式只有在原版 worker 的选择与浏览器实际代理配置、扩展控制权均匹配时显示勾选；未知或不匹配时不勾选。
- 模式名称按资料保存，重开在后台重新读取配置；上次提交结果未知时不自动重放。模式配置变化、观察失效或控制页变化时撤销本次匹配状态与缓存复用资格，不封锁普通网页请求；用户可发起新的明确选择。
- 配置、PAC 与认证参数留在原扩展文档内；原生界面只接收有长度限制的名称及当前勾选名称，不记入诊断日志。

2026-10-14 发布后修订：自动核对发现代理结果不匹配、未知、操作超时或观察超时，不弹出宿主提示窗口；保留实际代理核对、失效缓存请求及有限阶段诊断。手动操作无法执行的说明与游戏网页自己的对话框沿用原行为。

同日新增恢复要求：代理失败后允许从原生菜单明确选择一个新的情景模式，重新读取原版当前配置并执行新的操作，不因旧的未知标记永久禁用。正在执行的操作不并发提交；旧回复不能影响新操作。写入前预检失败不清除旧未知标记，新选择实际配置匹配并建立观察后才记为成功。启动及定时器不自动重放未知写入。

同日新增切换刷新：从代理菜单手动选择情景模式（含直连或重新选择当前模式），应用且实际配置核对成功后，自动刷新当前可见网页一次；双窗开启时副窗口也刷新自己的当前网址。持续观察不重复刷新；失败不刷新，仍允许重新选择。ZeroOmega控制/设置页、助手面板及正在进行的登录流程不刷新，不切换标签或将普通页面导航到主页。

最新启动修订：正常启动在指定组件就绪后直接访问 `https://game.granbluefantasy.jp/#mypage`，取消在线准备页和等待代理匹配才导航的门槛。使用WebView2当前实际网络/代理配置请求页面，后台恢复成功选择；启动时若实际应用了代理，匹配后刷新可见页面一次，以恢复先前失败的请求，只读核对不刷新。代理失配/超时不在宿主伪造403阻断普通网页，仍可访问、刷新、登录及切换模式。实际进程失败/关闭及显式离线诊断继续拒绝联网，TLS/CORS/CSP、沙箱和登录popup来源验证不变。新规则取代旧的在线准备页以及代理未匹配全局断网行为。

## 键盘快捷键（本地候选）

- 右侧快捷键图标位于双窗按钮上方、Tarou插件下方；点击打开原生配置浮窗。另一种浏览器布局在工具栏提供同一入口。
- 浮窗分通用操作、角色选择、角色技能、回复道具四组，含总开关、每项独立开关及单键绑定；同键可跨互斥界面复用，同一界面启用项不得冲突。支持清除绑定和恢复默认，不支持Fn或组合键，系统保留键可能被系统拦截。
- 默认 1–4 选择对应角色，在其他角色技能窗口先 Back 再选择；已在目标角色窗口不操作。QWER 点击当前角色四个技能，缺少技能不操作。角色选择和技能绑定不能冲突。
- 道具窗口 1–3 点击治疗药水、群体回复药水、Elixir；4–6 按活动药水 item-id 1–3 定位，缺失不操作，不猜测特殊名称。选择目标和道具确认仍由用户处理；六药水真实页面待用户验收。
- 通用默认 F5 刷新、反引号只点战斗 Back、C Quick 召唤、Z 召唤石面板、B 回复道具、A 攻击/取消攻击、F FC（含专用确认框 OK）、V 奥义发动/温存、Esc 战斗 Menu。需要主面板的操作先 Back；A 优先点击可见取消攻击按钮，不自动确认其他弹窗。
- 保存后生效，总开关、单项开关、绑定均保存在独立宿主状态文件，重启恢复，首次使用默认关闭。旧配置的默认键更新、自定义保留；冲突优先保留自定义，两个自定义冲突优先角色选择并关闭另一项。损坏配置保留原文件。
- 仅前台当前获得焦点的GBF游戏视图响应；刷新可在非战斗页使用，其他动作仅战斗路由。双窗按输入焦点选目标；输入框、可编辑区域、组合键、长按重复不触发；快速连按进入最多 32 项的先进先出预输入队列（满时不接收新项），旧动作完成后立即取下一项，重新识别当前页面状态；切换角色须等待目标面板及技能列表显示后再执行后续技能；召唤面板以实际展开列表确认就绪。失焦、导航、刷新、修改配置、手动移动鼠标、超时或目标校验失败清空队列，队列不保存到磁盘。
- 页面脚本仅读取元素状态和坐标，宿主通过Windows SendInput移动鼠标并点击，刷新调用当前WebView Reload。不调用游戏内部方法或战斗接口。每次按键最多一次 Back、一次目标点击及 FC 专用 OK 一次；普通动作最多 1.5 秒，FC 最多 3 秒，点击不重放。
- 鼠标保留小幅随机曲线，按接近初版即时移动的 8 毫秒参考时长、0.9–1 随机速度系数计算为 8–9 毫秒（实际受 Windows 定时器和页面校验耗时影响，已在目标处可直接点击）；点击前重新验证目标，用户手动移动鼠标会取消。曲线不承诺规避检测。
- 所有按键（含 Esc/功能键）统一使用原生输入；WebView 加速键仅抑制浏览器默认动作，不重复转发按键。坐标确认期间技能/道具界面身份或攻击/取消状态改变会取消操作；焦点、鼠标、页面、遮挡与目标可见性检查沿用。道具选择后不会继续点确认或目标。

## 本地资料导出、导入（0.1.12）

- 用户资料窗口增加“导出当前资料”和“导入资料”。当前阶段使用本地加密文件，不生成迁移码、不上传云端。
- 导出覆盖宿主持久布局与功能开关、快捷键总开关/逐项开关/绑定、Tarou Buff 标记、内置组件持久配置、书签、汉化持久配置和 WebView2 Cookie 接口提供的登录态。技能 CD 悬浮条总开关同时补为持久保存。
- 导出为密码加密的 `.sfprofile` 文件，至少 12 字符密码，导出须重复确认；不覆盖已有备份。错误密码、损坏或不支持的格式拒绝导入。
- 导入只创建新资料；导入资料的宿主设置位于其独立 `HostSettings`，不改写其他资料原有全局设置。原有普通资料继续沿用既有全局设置规则。窗口按目标机器屏幕/DPI 可见范围调整。
- 按组件角色匹配扩展数据，支持安装路径变化带来的扩展 ID 变化。恢复后回读核对，再关闭运行时并重开，防止旧 worker 缓存覆盖导入值；当前导入跳过 Cookie，恢复后需重新登录。失败返回原资料，失败的新资料归入已删除列表保留。
- 迁移视图不执行网页或插件初始化脚本，网站存储通过本地响应读取，不请求真实游戏页面；迁移内容不写入诊断日志。
- 当前不恢复登录态；不迁移密码管理器、网页历史、临时战斗状态或缓存。范围与文件规则见 [资料迁移](PROFILE_TRANSFER.md)。本轮真实账号跨机器验收仍待用户反馈。
