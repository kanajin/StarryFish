# 本地资料迁移（0.1.12）

入口为“用户资料”窗口中的“导出当前资料”和“导入资料”。迁移码、云端存储及自动同步不在本轮范围内。

## 使用方式

1. 在源电脑切换到要导出的资料，选择“导出当前资料”。选择一个新的 `.sfprofile` 文件名，输入并确认至少 12 个字符的密码。
2. 将文件复制到另一台电脑；在 StarryFish 中选择“导入资料”，选择该文件并输入原密码。
3. 导入创建一份新的资料，恢复配置后重新启动该资料。当前版本跳过归档中的 Cookie，请重新登录游戏。旧资料保留，可在资料窗口切换回去。导入资料使用独立的宿主设置目录，避免覆盖这台机器其他资料原有的布局和开关。

文件包含账号登录 Cookie、可能存在的代理凭据和汉化服务配置，应当作为私密备份保管。密码无法找回，不应与文件一起公开分享。导出不会覆盖已有备份文件。

## 数据范围

- 宿主窗口布局、双窗与助手面板设置、主题、加载画面和缓存开关、快捷键总开关与逐项配置、技能 CD 悬浮条开关。
- 四个内置组件各自的持久存储，包括 ZeroOmega 配置、Tarou Buff 标记和仅显示标记状态、肉鸽助手配置。扩展按产品角色匹配，不依赖源电脑的安装路径或扩展 ID。
- GBF 两个域名及支持的 Mobage 登录域名的网页 `localStorage`；其中包含书签数据、书签配置和汉化脚本的 `blhxfy:setting` 等持久设置。
- 导出的旧格式仍可包含 WebView2 Cookie，但当前导入只恢复配置，主动跳过 Cookie；不再以 Cookie 回读失败中止配置恢复。

不复制浏览器原始数据库、操作系统加密密钥、密码管理器、浏览历史、下载文件、网页缓存或当前战斗进度。网页临时 `sessionStorage` 与脚本代码本体也不作为配置迁移；脚本版本由目标 StarryFish 提供。服务器可能拒绝已经过期或绑定设备的会话，迁移不保证免于重新登录。

## 文件与失败处理

格式版本为 `SFPACK01`，使用随机盐、PBKDF2-HMAC-SHA256（600,000 次）及 AES-256-GCM 验证加密；密码按 UTF-16LE 编码。数据仅在本机处理，不上传服务器。错误密码、内容损坏或不支持的格式在创建资料前拒绝。

新资料恢复后回读扩展和网页存储进行核对；失败不激活新资料，返回原资料。现有资料不被导入覆盖。不同屏幕尺寸和 DPI 下窗口仍按宿主现有规则调整到可见范围。

## 验证范围

构建、加密隔离检查、实际组件的合成资料导出/导入及重启检查通过；用户真实归档与跨机器恢复仍待验收。
